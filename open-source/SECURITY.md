# 安全政策

## 支持范围

安全修复优先应用到当前维护版本。当前开源发布线为：

- 手机端与手表端：`0.2.x`

旧版本和早期 HarmonyOS 实验工程不保证获得修复。报告问题时请提供实际版本号，但不要附带任何真实账户数据。

## 请私密报告的问题

- 密钥、验证码、激活码或加密备份可被未授权读取。
- 应用锁、紧急密码、连续错误自毁或最近任务隐私可被绕过。
- 导入 / 导出、离线语言包或双端同步可执行非预期操作。
- 广播、文件路径、ADB 连接或第三方组件导致越权访问。
- 依赖中存在可影响本项目的已知漏洞。

普通界面问题、功能建议和不涉及安全影响的崩溃，请使用公开 Issue。

## 报告方式

1. 首选主仓库 GitHub 的 **Security → Advisories → Report a vulnerability** 私密报告功能。
2. 若该功能尚未启用，请通过仓库维护者公开资料中提供的私密联系方式报告；在确认渠道前不要公开漏洞细节。
3. Gitee Issue、GitHub Issue、Discussion 和 Pull Request 都不得用于披露未修复漏洞。

维护者启用 GitHub 私密漏洞报告的步骤见根目录 [OPEN_SOURCE.md](../OPEN_SOURCE.md)。

## 报告内容

请提供：

- 手机端 / 手表端版本、系统版本和设备类型。
- 受影响页面、配置和触发条件。
- 最小复现步骤、预期结果与实际结果。
- 影响范围、可能后果和建议修复方向。
- 脱敏日志或截图；必要时使用专门创建的测试账号。

**不要发送真实 TOTP 密钥、`otpauth://` 链接、当前验证码、激活码、应用锁密码、私钥、签名文件、ADB 私钥或完整导出文件。** 如必须演示格式，请使用明确标记的随机测试数据。

## 处理原则

- 维护者会先确认报告并评估影响，再安排修复与发布。
- 在修复可用前，请避免公开细节或利用漏洞访问他人数据。
- 修复说明只描述必要信息，不包含可利用的敏感样本。
- 本项目为离线个人工具，不承诺漏洞奖励或固定响应时限。

## 使用者的安全建议

- 只从项目官网或维护者确认的 Release 下载安装包，并核对 SHA-256。
- 为手机、手表和应用锁使用不同且可靠的凭据。
- 导出备份应加密，并像保存原始密钥一样保管。
- 不使用时关闭手表 ADB / 无线调试，避免不可信设备接入。
- 丢失设备或怀疑密钥泄露时，应立即在对应服务处重置两步验证。
